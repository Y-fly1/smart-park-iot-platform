# 联系人小程序登录 · 实现说明

> 接口：`POST /member/user/login`
> 入参：`code`、`nickName`、`phoneCode`
> 返回：`{ token, nickName }`

---

## 一、整体链路

```
小程序 wx.login()                          ──> code
小程序 button open-type="getPhoneNumber"   ──> phoneCode
        │
        ▼
POST /member/user/login  { code, phoneCode, nickName }
        │
        ▼
MemberUserController.login()               // 只收参数，不做业务
        │
        ▼
ContactServiceImpl.login()            // 六步业务逻辑
        ├─ WxMiniAppClient.code2Session(code)        → openid
        ├─ 按 openid 查 contact
        ├─ WxMiniAppClient.getPhoneNumber(phoneCode) → phone
        ├─ 联系人不存在 → 新增；存在但手机号变了 → 更新
        └─ TokenService.createToken(paramMap)        → token
        │
        ▼
{ token, nickName }
```

## 三、微信接口封装：`WxMiniAppClient`

### 1. code2Session —— 用 code 换 openid

```java
HttpUtil.get("https://api.weixin.qq.com/sns/jscode2session", params);
// params：appid、secret、js_code = code、grant_type = authorization_code
```

- 这个接口**不需要 access_token**，只要 appid + secret + code
- 返回 `openid`、`session_key`
- **openid 是「该微信用户在该小程序内」的唯一标识**，作为找人依据

### 2. getPhoneNumber —— 用 phoneCode 换手机号

这个接口多一环，**必须先拿到 access_token**：

```
GET  /cgi-bin/token?grant_type=client_credential&appid=&secret=
     ← access_token（有效期 7200 秒）

POST /wxa/business/getuserphonenumber?access_token=xxx
     body: {"code": phoneCode}
     ← {"errcode":0, "phone_info": {"phoneNumber": "13800138000"}}
```

`access_token` 是调用微信 API 的全局通行证，有每日调用次数限制，所以**不能每次都去换**：

```java
redisCache.setCacheObject(cacheKey, accessToken,
        expiresIn - 300, TimeUnit.SECONDS);
```

> 比 `expires_in` 提前 300 秒失效，避免「缓存里的 token 还在、微信那边刚好过期」导致调用失败。
> 缓存 key 为 `wx:miniapp:access_token:{appid}`，多小程序共用一个 Redis 也不会串。

### 3. 统一错误处理

微信无论成功失败都返回 HTTP 200，错误藏在 `errcode` 里，因此每次调用后都要校验：

```java
int errCode = result.getInt("errcode", 0);
if (errCode != 0) {
    throw new ServiceException("微信接口调用失败：" + result.getStr("errmsg"));
}
```

抛 `ServiceException` 后由若依全局异常处理器接管，前端收到 `{"code":500,"msg":"..."}`，不会暴露堆栈。

## 四、业务逻辑：`ContactServiceImpl.login()`

```java
// 1. code → openid
String openId = wxMiniAppClient.code2Session(dto.getCode());

// 2. 按 openid 查联系人
Contact member = lambdaQuery()
        .eq(Contact::getOpenId, openId)
        .orderByDesc(Contact::getId)
        .last("limit 1")
        .one();

// 3. phoneCode → 手机号
String phone = wxMiniAppClient.getPhoneNumber(dto.getPhoneCode());

// 4. 不存在 → 新增
if (member == null) {
    nickName = generateNickName(phone);     // 四字前缀 + 手机号后四位
    member = new Contact();
    member.setOpenId(openId);
    member.setPhone(phone);
    member.setName(nickName);
    member.setCreateTime(DateUtils.getNowDate());
    save(member);                            // 自增 id 自动回填
}
// 5. 存在 → 手机号不一致才更新
else if (!phone.equals(member.getPhone())) {
    member.setPhone(phone);
    member.setUpdateTime(DateUtils.getNowDate());
    updateById(member);
}

// 6. 生成 token
Map<String, Object> paramMap = new HashMap<>();
paramMap.put("userId", member.getId());
paramMap.put("nickName", nickName);
String token = tokenService.createToken(paramMap);
```

### 设计要点

| 要点 | 说明 |
|---|---|
| **第 2、3 步顺序不能反** | openid 用于「找谁」，手机号用于「改成什么」，先定位再更新 |
| **用 openid 而非手机号判断是否存在** | 用户可能换绑手机号，但 openid 跟着微信账号走，稳定 |
| **`@Transactional`** | 新增失败时整体回滚，不留下半截用户 |
| **`limit 1` 兜底** | 唯一索引已防重复，此处仅作防御性写法 |

### 昵称生成

```java
private static final List<String> NICK_NAME_PREFIX_LIST = Arrays.asList(
        "大吉大利", "今晚吃鸡", "福星高照", "好事发生",
        "匆匆忙忙", "连滚带爬", "从从容容", "游刃有余");

private String generateNickName(String phone) {
    List<String> list = new ArrayList<>(NICK_NAME_PREFIX_LIST);
    Collections.shuffle(list);                        // 打乱
    String prefix = list.get(0);                      // 取第一个
    String postfix = phone.length() >= 4
            ? phone.substring(phone.length() - 4)     // 手机号后四位
            : RandomUtil.randomNumbers(4);            // 兜底：随机四位数字
    return prefix + postfix;                          // 例：好事发生8915
}
```

> Hutool 里没有 `RandomStringUtils`（那是 commons-lang3 的类），对应方法是 `RandomUtil.randomNumbers(4)`。

## 五、Token 生成：容易踩的坑

若依 `TokenService` 有两个 `createToken` 重载，行为完全不同：

| 重载 | 做了什么 | 结果 |
|---|---|---|
| `createToken(LoginUser)` | 生成 uuid，把整个 `LoginUser` **存进 Redis**，JWT 只放 uuid | 有状态会话，可续期、可踢下线 |
| `createToken(Map<String, Object>)` | **只把 Map 签进 JWT**，不碰 Redis | 无状态令牌，信息自带 |

本项目走的是第二个：

```java
String token = tokenService.createToken(paramMap);  // HS512 签名，密钥为 token.secret
```

生成的 JWT 形如 `header.payload.signature`，payload 里能解出 `userId` 和 `nickName`——接口文档示例 token 用 base64 解码后能看到 `"userid":1` 就是这个原因。

### ⚠️ 重要后果

这个 token **不被若依标准登录过滤器识别**。`TokenService.getLoginUser()` 解析出 uuid 后会去 Redis 找 `login_tokens:xxx`，而这里没存，所以拿到的是 `null`。

- 当前用法没问题：token 只是「带签名的身份凭证」，会员端接口自行解析使用
- 若将来会员端接口要挂 `@PreAuthorize` 或 `SecurityUtils.getLoginUser()`，需要为会员端单独实现过滤器和解析逻辑

## 六、配置与放行

### 配置

```yaml
wx:
  miniapp:
    appid: ${WX_MINIAPP_APPID}
    secret: ${WX_MINIAPP_SECRET}
```

通过 `@ConfigurationProperties(prefix = "wx.miniapp")` 绑定到 `WxMiniAppProperties`，换环境只改配置文件，secret 不散落在代码里。

### 放行

`SecurityConfig` 中已有：

```java
requests.requestMatchers("/login", "/register", "/captchaImage", "/member/**", "/ai/chat").permitAll()
```

`/member/**` 已放行，登录接口无需 token 即可访问——这是必须的，否则「拿 token 的前提是先登录」会变成死循环。

## 七、数据库

`contact` 表新增唯一索引：

```sql
UNIQUE KEY `uk_open_id` (`open_id`) USING BTREE
```

已同步到 `sql/zhiwei.sql` 和 `sql/小程序.sql` 的建表语句。

**已存在的库需手动执行：**

```sql
-- 1. 先检查重复 openid（有重复则 ALTER 会失败，需先清理）
SELECT open_id, COUNT(*) FROM contact
WHERE open_id IS NOT NULL GROUP BY open_id HAVING COUNT(*) > 1;

-- 2. 加唯一索引
ALTER TABLE `contact` ADD UNIQUE INDEX `uk_open_id` (`open_id`) USING BTREE;
```

## 八、已知限制与后续优化

| 项 | 现状 | 建议 |
|---|---|---|
| 入参 `nickName` | 收到但未使用，昵称统一由后端生成 | 如需优先使用微信昵称，加一个判空分支 |
| 并发重复登录 | 同一微信并发首次登录，第二次 `save` 会抛 `DuplicateKeyException`，前端见 500 | 低频场景暂不处理；如出现可 catch 后回查重试 |
| access_token 缓存 | 存 Redis，多实例共享 | 已满足多实例部署，无需改动 |
| token 校验 | 纯 JWT，无 Redis 会话 | 会员端如需鉴权，需单独的过滤器 |

## 九、排查思路

| 现象 | 可能原因 |
|---|---|
| 提示「获取微信openid失败」 | code 已使用或已过期（code 一次性、5 分钟有效） |
| 提示「获取微信access_token失败」 | appid / secret 配置错误，或微信后台 IP 白名单限制 |
| 提示「获取微信手机号失败」 | phoneCode 失效；或小程序未开通「手机号快速验证」能力 |
| 登录成功但 token 用不了 | token 为无状态 JWT，标准过滤器不识别，需自行解析 |
